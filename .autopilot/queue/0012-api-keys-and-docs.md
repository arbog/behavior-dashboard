## Goal

People will want to automate against the board (a home-automation "morning
routine" that checks the battery, a script that pulls the ABC log into a
spreadsheet, a voice assistant that logs a behavior). Today the only
non-browser credential is the session cookie (needs a browser) or the kiosk
code (child-scoped, and it can tap). Add **admin-scoped API keys**:

- New table `api_keys (id, name, key_hash, created_at, last_used_at,
  revoked_at)`. `key_hash` is SHA-256 of the raw key. Raw key format
  `bdb_` + 48 hex chars (32 bytes), shown ONCE at creation.
- Auth: on `/api/admin/*` routes, an `Authorization: Bearer bdb_…` (or
  `x-api-key: bdb_…`) header matching a non-revoked key authenticates as the
  admin (same gate, same audit, same rate limits — keys do not bypass the
  300/min admin limit; they ARE an identity for `by`/audit: use
  `by = 'api:<name>'` where a `user` string is recorded). A key NEVER
  authenticates `/api/today*` (kiosk surface stays kiosk-token-only).
  Keys are checked only when there is no valid session cookie (cookie wins,
  so a logged-in browser is unaffected).
- Endpoints (admin-gated, audited `api_key_*`):
  - `POST /api/admin/api-keys { name }` → `{ id, name, key }` (raw key once)
  - `GET /api/admin/api-keys` → `[{ id, name, created_at, last_used_at,
    revoked_at, prefix }]` where `prefix` is `bdb_` + first 8 hex (enough to
    tell keys apart, never enough to use one)
  - `DELETE /api/admin/api-keys/:id` → soft revoke
  Cap 5 active keys (400 above). `name` required 1–40 chars.
- Update `GET /api/admin/security` to include `api_keys` count + last-used
  (so the security card reflects automation), and add the `api_key_*` events
  to the audit kinds.
- **`docs/api.md` (new)**: the full public API reference. Every routed path
  (kiosk, admin, auth, export, sessions, kiosk devices, security) with:
  method, auth required, request shape, response shape, error shapes. This
  doc is generated by hand for now — include a "keep in sync" note at the
  top and a machine-checkable list of route paths in the acceptance below
  so drift is caught.

## Acceptance

```sh
node --test
node -e "
process.env.DB_PATH = ':memory:';
process.env.SETUP_TOKEN = 'd'.repeat(64);
const { server } = require('./server.js');
server.listen(0, async () => {
  const base = 'http://127.0.0.1:' + server.address().port;
  const setup = await fetch(base + '/api/admin/setup', { method: 'POST', headers: { 'content-type': 'application/json' }, body: JSON.stringify({ password: 'correct-horse-battery', token: 'd'.repeat(64) }) });
  const ck = setup.headers.get('set-cookie').split(';')[0];
  const H = { cookie: ck, 'content-type': 'application/json' };
  const created = await (await fetch(base + '/api/admin/api-keys', { method: 'POST', headers: H, body: JSON.stringify({ name: 'home-auto' }) })).json();
  if (!/^bdb_[0-9a-f]{48}$/.test(created.key || '')) throw new Error('key format wrong: ' + created.key);
  // key works without a cookie
  const withKey = await fetch(base + '/api/admin/config', { headers: { 'authorization': 'Bearer ' + created.key } });
  if (withKey.status !== 200) throw new Error('key must authenticate admin API, got ' + withKey.status);
  // key does NOT work on the kiosk surface
  const onKiosk = await fetch(base + '/api/today', { headers: { 'x-kiosk-token': created.key } });
  if (onKiosk.status !== 401) throw new Error('key must not authenticate kiosk, got ' + onKiosk.status);
  // cookie still wins / independent
  const del = await fetch(base + '/api/admin/api-keys/' + created.id, { method: 'DELETE', headers: H });
  if (del.status !== 200) throw new Error('revoke must be 200');
  const dead = await fetch(base + '/api/admin/config', { headers: { 'authorization': 'Bearer ' + created.key } });
  if (dead.status !== 401) throw new Error('revoked key must be dead, got ' + dead.status);
  server.close();
  console.log('api-keys-ok');
});
" | grep -q api-keys-ok

const s = require('node:fs').readFileSync('server.js','utf8');
const d = require('node:fs').readFileSync('docs/api.md','utf8');
const routes = [...s.matchAll(/p === '([^']+)'/g)].map(m => m[1]).filter(r => r.startsWith('/api/') || r === '/healthz');
const missing = routes.filter(r => !d.includes(r));
if (missing.length) throw new Error('docs/api.md missing routes: ' + missing.join(', '));
console.log('api-docs-cover ' + routes.length + ' routes');
"
grep -q "API keys" docs/security-model.md
```

## Stop and ask if

- a key should be able to scope down (read-only vs full) — default: NO,
  first keys are full-admin-scoped and we note read-only keys as a future
  item; ask if you think a household needs read-only keys NOW
- the `by` audit attribution for key-driven writes should include the key
  name (default: yes, `api:<name>`); ask if that leaks too much into a
  child's record

## Notes for the agent

- The route-coverage check in acceptance parses `p === '<path>'` literals —
  keep new admin routes in that style (you already are) so the doc check
  stays honest.
- Do not let a Bearer header change the login/setup/logout flow — those stay
  cookie/session based.
